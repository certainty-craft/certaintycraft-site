Context

A multi-brand healthcare content team was adopting AI tools faster than it was adopting rules for them. Prompts lived in chat histories and personal docs: unversioned, unreviewed, and quietly diverging from the brand, legal, and terminology decisions the team had already made.

The problem, precisely

Prompts rot. A prompt that worked in March contradicts the terminology decided in May. Without governance, every writer rebuilds the same instructions, and an AI tool receives whichever version someone happened to save. The failure is not the model. It is the library.

What I built

Promptorium: 87 production prompts organized in five themed collections, each prompt a versioned asset with YAML front matter, a flat prefixed tag namespace, and review gates. A Python regeneration pipeline rebuilds the catalog indexes from the files themselves, so the catalog never drifts from reality. The prompts encode the systems around them: quality evaluation, legal risk scanning structure, findability review, and terminology the taxonomy had already settled.

Honest status

Shipped and in daily team use before the company's acquisition. A public edition, sanitized of client names and internal terminology, shares the architecture, sample prompts, and the regeneration tooling pattern on GitHub.

What this demonstrates. AI content operations is governance work. A prompt library is not a folder of clever instructions; it is a versioned, reviewable asset that carries the organization's decisions into every AI interaction. I build the library so the tools inherit the rules.

Artifacts available on request: the public repo (github.com/PHDAE/promptorium-public), architecture docs, sample prompts, regeneration tooling pattern.
